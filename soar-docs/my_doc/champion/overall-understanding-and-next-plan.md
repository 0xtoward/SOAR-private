# SOAR MiniCPM-SALA：冠军路线复读后的总理解与下一步计划

## 一句话结论

到 `Week 5` 为止，冠军路线传递出来的核心不是“不断换主线”，而是：

1. 先建立高置信本地评测和稳定工程链路
2. 先拿下 `W4A16 + GPTQ + Marlin` 这种真正命中 decode 带宽瓶颈的主路线
3. 再用混合精度、层敏感性分析、KV Cache 压缩去补速度
4. 全程把精度门槛当作硬约束，而不是附属指标

对我们当前局面来说，真正的瓶颈已经不是“能不能跑起来”，而是：

> 怎么在 submission-safe 的前提下，把官方 `acc` 从 `95.x` 推到 `97+`。

---

## 1. 对 Week 1~5 的统一理解

## Week 1：先承认评分函数是精度门槛驱动的

第一周最重要的不是某个具体优化，而是：

- 评分函数里 `C < 97%` 会直接归零
- 但短输入 decode 速度又占很大权重

所以这周给出的第一个真结论是：

- `W4` 权重量化的速度收益足够大，必须认真做
- 但精度不能只是“差不多”，必须跨过硬门槛

## Week 2：混合精度不是锦上添花，而是必要策略

第二周核心是：

- 全局低比特虽然快，但精度会掉
- 所以必须给敏感部分保精度

这周的真正启发不是具体哪层该保，而是：

> 量化路线默认不该是一刀切，而该是混合精度。

## Week 3：校准数据和评测代理决定你是否会被假信号骗

第三周最值钱的收获有两个：

- 要分析评测集任务分布，尤其识别 `fwe/cwe` 这种低语义信号任务
- 要有比“最后一道分数”更早、更稳的代理指标

这周还把 `NVFP4` 正式带入视野，但重点其实不是“FP4 更先进”，而是：

- Blackwell 硬件确实给了低比特新的机会
- 但低比特能不能成，依然取决于精度评估和敏感层保护

## Week 4：冠军主线真正坐实

第四周把路线讲得最清楚：

- `decode` 更偏 `memory-bound`
- 真正命中瓶颈的是 `W4A16 + GPTQ + Marlin`
- 校准集质量非常关键
- 本地高置信测试比盲提交流程更重要

这一周对我们的意义最大，因为它和我们后续最成功的路线高度同构。

## Week 5：不是换主线，而是在主线上继续做混合精度

第五周很多人会误读成“冠军靠 NVFP4 赢了”，但更准确的理解是：

- 主干仍然是 `W4A16 + GPTQ + Marlin`
- 新增的是 `NVFP4 KV Cache`
- 而且是逐层敏感性分析之后的混合精度 `KV Cache`

真正的结论不是“NVFP4 万能”，而是：

> 当某个低比特方向精度不够时，正确的补救往往不是放弃，而是对敏感层保高精度。

---

## 2. 我们这条线真正学到了什么

## 做对了什么

### 1. 我们已经把最可行的 submission-safe 主干搭出来了

这部分不是猜测，而是已经被官方提交结果和本地 full/medium 路线验证过：

- 双 env 分离是必要的
- dense fallback 是当前能稳定 serve/eval 的路线
- tokenizer 资产回灌和自检是必须补丁
- `W4A16 + GPTQ + Marlin` 已经能稳定提交和出分

### 2. 我们找到了一个真实问题：over-generation / stop boundary

这不是推测，而是从本地 medium 和 overgen 子集里反复看到的：

- 问题不是 stop 字符串没传进去
- 也不是 sparse kernel 本身造成的
- 主因是量化后 stop/EOS 边界不稳，导致少数样本极端 over-generation

这一步很关键，因为它把问题从“系统没跑通”推进到了“行为到底哪里变差”。

### 3. `stop-aligned calibration` 证明了校准分布真的会改行为

它带来的不是更快 kernel，而是：

- 输出 token 显著减少
- 一部分 stop 边界更稳
- local fast/medium proxy 一度明显变好

所以这条线至少证明了一件事：

> GPTQ 成败不只看 kernel 和 bit 数，校准分布本身就会决定模型生成行为。

## 做错了什么

### 1. 我们一度把失败的 NVFP4 权重量化，误当成了冠军 NVFP4 的近邻

这后来已经被事实推翻了。

我们的失败路线是：

- `ModelOpt NVFP4` 权重量化

而冠军第五周做成的是：

- `NVFP4 KV Cache` 混合精度

两者不是一条路。

### 2. 我们最近的 selective `C` 动了 attention，风险比预期大

`C` 这条线做的是：

- `o_proj/down_proj`
- 再加上 `q/k/v -> gs64`

虽然工程上最终修到了可加载，但结果上官方 `acc` 掉到了 `94.94`。

这说明：

- 对当前 MiniCPM-SALA 路线来说
- attention 侧 selective 改动非常容易伤到答案边界

### 3. 我们还没有把“local proxy 为什么和官方不完全一致”彻底收口

我们已经有越来越好的 local medium/full 验证，但仍然有过这种情况：

- 本地 proxy 看起来不错
- 官方 `acc` 没能稳定兑现到 `97+`

这意味着后面不能只看局部子集或单次 medium，还需要更系统地对齐 full public set。

---

## 3. 现在最可信的总判断

## 判断 1：当前真正的主瓶颈是精度，不是速度

官方最近几次结果已经说明：

- 速度不是完全不重要
- 但当前 `S1/S8/Smax` 已经不差
- 真正卡分的是 `acc` 还在 `95.x`

所以现在最值钱的每一次实验，都应该优先问：

> 这件事有没有希望把 `acc` 往 `97+` 推，而不是只带来一点点更快。

## 判断 2：当前最可信主线仍然是 `W4A16 + GPTQ + Marlin`

理由不是“冠军说了”，而是我们自己的结果已经验证：

- 这条线 submission-safe
- 这条线能稳定跑
- 这条线已经接近最好的官方结果

反过来：

- `ModelOpt NVFP4` 权重量化目前对 MiniCPM-SALA 不是一条健康主线

## 判断 3：attention 侧 broad selective 现在不值得继续硬推

我们已经拿到了足够的负面证据：

- `q/k/v` 这类改动不仅工程兼容性差
- 就算修到能跑，也不自动带来更高 `acc`
- 还更容易把少数原本正确的题推翻

所以目前更稳的纪律应该是：

- 不再把 attention 当作 first-choice 修复面

## 判断 4：`stop-aligned` 说明“校准分布重要”，但它还不是最终答案

它值得保留为方法论资产，但不应该被神化。

更准确的结论是：

- 它证明了 calibration 可以改变 stop 行为
- 但还没有证明自己是通往 `97+` 的稳定最终路线

---

## 4. 对我们当前最有价值的执行原则

## 原则 1：先保护正确率门槛，再拿速度收益

只要某条路线：

- 不能把官方 `acc` 推到 `97+`

那么再快也没有最终分数意义。

## 原则 2：优先做“窄而可解释”的实验，不做“大而漂亮”的实验

例如：

- 动很少的模块
- 只改一个关键假设
- 能明确解释为什么涨/为什么跌

比：

- 同时改校准、attention、penalty、serve 参数

更有价值。

## 原则 3：区分“工程修通”和“精度提升”

我们已经见过：

- fused `qkv_proj` runtime patch 让 checkpoint 能加载

但这不等于：

- checkpoint 更准

后面每次都必须把这两件事分开记录。

## 原则 4：如果重看 NVFP4，必须换问题定义

不要再问：

- “旧的 ModelOpt NVFP4 权重量化能不能再救一下？”

而要问：

- “有没有 `KV Cache` / 混合精度 / 新 kernel 支持 的新路线？”

---

## 5. 下一步计划

## A. 主线：继续围绕 `W4A16 + GPTQ + Marlin`

### A1. 先把 full public-set local-vs-official 对齐做实

目标：

- 用 full public set 本地复现去判断，当前 local harness 和官方结果到底差多少
- 不再只靠局部 medium / focus10 去猜官方方向

产出应包括：

- 逐条得分变化
- 逐条输出长度变化
- 哪些任务类型最容易翻错

### A2. 暂停 broad attention selective

短期内先不继续推：

- `q/k/v -> gs64`
- attention 大范围 selective override

原因：

- 这条线已经给出了负面官方结果
- 并且违背了“先保护敏感层”的更稳原则

### A3. 如果继续做 selective，只考虑更窄、更保守的非 attention 修复

优先级应是：

1. 不动 attention
2. 只动 MLP 相关模块
3. 每次只改一小组模块

如果这都不能带来净收益，再考虑是不是应该停止 selective GPTQ 这条线。

## B. 校准线：继续研究，但不要再把它当万能钥匙

### B1. 可以试更贴官方分布的 prompt-only calibration

如果要进一步 benchmark-align，一个合理实验是：

- 直接用 full `public_set` 的 prompt 做 calibration
- 不默认把 gold answer 全部拼进去

因为：

- GPTQ 量化本身不需要 decode
- 单独存 output 字段也没用
- 真正有影响的是 `calib_text` 本身

### B2. `chat_close` 只保留小比例，不要全量依赖答案文本

原因：

- 它可以帮助模型看到正常收尾状态
- 但如果把全部 gold answer 都塞进 calibration text，过拟合和标签泄漏意味都太强

## C. NVFP4 线：从“旧权重量化补丁”转为“新路线储备”

如果回头看 NVFP4，下一次应该满足三个条件：

1. 不是沿用旧的 `ModelOpt NVFP4` submission scaffold 小修补
2. 优先考虑 `KV Cache` 而非全模型权重量化
3. 必须带混合精度或敏感层分析，而不是全层一刀切

在没有这三个条件之前，NVFP4 不应该重新升为主线。

---

## 6. 当前建议的路线排序

1. `W4A16 + GPTQ + Marlin`，继续做 full public 对齐与更窄修复
2. calibration 继续做 prompt-only / 小比例 chat-close 的更稳实验
3. 暂停 broad attention selective
4. NVFP4 保留为未来新路线，不再把旧 scaffold 当主力

---

## 最终收束

如果把 Week 1~5 和我们自己的得失一起压成一句话，那就是：

> 冠军路线从来不是“找到一个神奇开关”，而是先把主路线做对，再只对真正敏感的部分保精度、做混合精度、做校准；而我们接下来最该做的，就是把这套方法论落到 `97+ acc` 这个硬目标上，而不是继续在已经证明风险很高的 attention selective 或旧 NVFP4 权重量化上消耗时间。
