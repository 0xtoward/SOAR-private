# Week 4 — 智算一队：W4A16 量化与推理算子融合实践（周冠军）

## 总体路线

第四周冠军路线不是单点技巧，而是三部分协同：

1. 先做可靠的本地基础设施
2. 再做模型代码和推理算子优化
3. 最后把主要收益压在 `W4A16 + GPTQ + Marlin`

## 1. 基础设施先行

- 先把 `SGLang + MiniCPM-SALA` 推理链路完整跑通
- 自建本地高置信评测集，尽量贴近官方速度集长度分布
- 由于每天只有 3 次提交机会，本地评测的作用是先过滤掉低概率方案
- 还分析了官方精度评测集的任务类型和输入长度分布，为校准数据准备服务

## 2. 算子融合

- 先梳理前向计算路径，找可融合点
- 重点示例：
  - `RMSNorm + 残差` 融合
  - `RoPE` 相关路径优化
- 核心目标是减少 kernel launch、降低无效 dtype 转换和前向开销

## 3. 量化路线选择

### 试过但收益有限的方案

- `W8A8` 动态量化：速度几乎没变化
- `W8A16`：精度比较稳，但性能提升不足

### 最终主路线

- `W4A16`
- `GPTQ + Marlin`

## 为什么是 W4A16 + GPTQ + Marlin

- 冠军判断 decode 阶段更偏 `memory-bound`
- `W4` 能显著降低带宽压力
- `GPTQ` 比简单 RTN 更能保精度
- `Marlin` 在小 batch decode 场景更容易接近理论带宽收益

一句话：

> 他们不是为了“把模型量到 4bit”而量化，而是为了命中 decode 带宽瓶颈，选择更适合该瓶颈的 `W4A16 + GPTQ + Marlin`。

## 校准数据的重要性

- 校准数据对量化精度影响很大
- 他们根据评测任务分布反复迭代校准数据配比
- 这意味着：量化效果不仅由算法决定，也由校准数据质量决定

## 对我们最重要的启发

1. 不要只做“局部 selective AWQ mask 调参”
2. 要优先寻找真正命中 decode 带宽瓶颈的路线
3. `W4A16 + GPTQ + Marlin` 应视为最高优先级候选
4. 如果做 `NVFP4` / `modelopt_fp4`，也应当把它看成“另一条真正命中硬件路径的候选”，而不是泛泛试量化
5. 本地高置信测试和校准数据迭代是必须项，不是附属项

## 给自动化 Agent 的执行含义

- 先读清本地已有 `SGLang` 源码和测试入口
- 优先复用本地量化/导出/加载实现，不要先假设必须从零安装整套工具链
- 先用最小实验验证 `GPTQ + Marlin` 或 `modelopt_fp4` 导出链是否能跑通
- 只要候选路径形成，就立刻测试，不要长时间停留在阅读阶段
