# `rtx6000-1` 上 `nsys/ncu` 环境摸索纪要（2026-04-20）

## 一句话结论

`rtx6000-1` 这台机子上，**`nsys` 能稳定用，`ncu` 当前拿不到 GPU performance counters**。  
所以现阶段最可靠的分析路线是：

1. 用 `nsys` 做系统级时间归因
2. 用 NVTX 包住 isolated case 做局部拆账
3. 暂时不要指望 `ncu` 给出 occupancy / stall / L2 hit 这类硬件计数器图

## 当前真实可用结论

### `nsys`

可稳定跑：

- detached server + bench 整体 profiling
- isolated Python case profiling
- `cuda_gpu_kern_sum`
- `cuda_api_sum`
- `osrt_sum`
- `nvtx_gpu_proj_sum`
- `nvtx_pushpop_sum`

也就是说，现在能稳定回答：

- GPU 时间花在哪些 kernel 上
- CPU API 时间大头在哪
- NVTX 标出的阶段各占多少 GPU 时间
- prefill-heavy / decode-heavy 不同时间窗里谁是热点

### `ncu`

当前会稳定报：

```text
==ERROR== ERR_NVGPUCTRPERM - The user does not have permission to access NVIDIA GPU Performance Counters on the target device 0.
```

这意味着当前**拿不到**：

- SM occupancy
- warp stall reason
- Memory Throughput / L2 hit
- Scheduler Stats
- Roofline / Speed-of-Light 这类硬件计数器图

所以现在要明确区分：

- `ncu` 二进制是存在的
- 但 **host/container 权限** 没给 counters
- 问题不在 Python env，也不在命令写法

## 推荐命令

## 1. 核对环境

```bash
ssh rtx6000-1 '
/opt/nvidia/nsight-compute/2025.1.1/host/target-linux-x64/nsys --version
/opt/nvidia/nsight-compute/2025.1.1/ncu --version
'
```

## 2. 跑系统级 `nsys`

```bash
ssh rtx6000-1 '
bash /root/autodl-tmp/codex-drafts/run_nsys_extreme_server_detached.sh \
  /root/autodl-tmp/models-gptq-w4a16-py310-attnqkv-allowlist-v1-gate0-fixorder \
  attnqkv-gate0-nsys-prefill \
  120
'
```

最后一个参数是采样窗口秒数，可以按需要改成偏 prefill 或偏 decode。

## 3. 跑 isolated `SimpleGLA`

```bash
ssh rtx6000-1 '
cd /root/autodl-tmp/codex-drafts/w4a16-marlin-fusion-kvcache-probe-v1
/opt/nvidia/nsight-compute/2025.1.1/host/target-linux-x64/nsys profile \
  -o /root/autodl-tmp/SOAR-Toolkit/test_results/nsys_simple_gla_demo/demo \
  --trace cuda,nvtx,osrt \
  /root/autodl-tmp/codex-drafts/w4a16-marlin-fusion-kvcache-probe-v1/runtime_envs/eval_py310_env/bin/python \
  profile_simple_gla_case.py \
  --variant fused \
  --batch 128 \
  --seq-len 1 \
  --include-state-io
'
```

## 4. 验证 `ncu` 权限

```bash
ssh rtx6000-1 '
/opt/nvidia/nsight-compute/2025.1.1/ncu \
  --set full \
  --target-processes all \
  /root/autodl-tmp/codex-drafts/w4a16-marlin-fusion-kvcache-probe-v1/runtime_envs/eval_py310_env/bin/python \
  /root/autodl-tmp/codex-drafts/w4a16-marlin-fusion-kvcache-probe-v1/profile_simple_gla_case.py \
  --variant fused --batch 128 --seq-len 1
'
```

如果环境没变，预期仍然是 `ERR_NVGPUCTRPERM`。

## 现在能信什么，不能信什么

## 能信

- `nsys` 的 kernel 时间占比
- `nsys` 的 NVTX 阶段拆账
- isolated case 的相对趋势
- prefill / decode 热点差异

## 不能信

- 当前机器上的 `ncu` occupancy / stall / L2 hit
- 任何基于“应该能拿到 counters”的推断

---

## 当前最推荐的实践

1. 系统级先看 `nsys`
2. 需要拆细时，用 `profile_simple_gla_case.py + NVTX`
3. 在 host 打开 GPU performance counters 之前，不要重押 `ncu`
4. 如果要继续优化 `SimpleGLA`，优先看 decode 路线，不要先盯 prefill chunk
